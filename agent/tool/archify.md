# archify：把方案讲成可交互的 HTML 图

**仓库**：<https://github.com/tt-a1i/archify>
**类型**：Skill

把"你想讲清楚的东西"变成**可交互的 HTML 图**。起点可以是一个想法、一个问题、一个方案，也可以让 agent 直接读仓库生成有出处依据的架构图。

产出是能点开、能探索、能分享的 HTML，比静态截图强很多。README 里的例子包括系统架构图（"浏览器调 API，API 查 Redis，缓存 miss 就去 PostgreSQL 查并回填缓存"）和行程规划、学习地图这类非技术内容。

## 没有它之前

| 做法 | 代价 |
|---|---|
| draw.io / Excalidraw 手画 | 布局、对齐、连线全手调；方案一变就重画 |
| Mermaid 写在 Markdown 里 | 自动布局不可控，复杂图上会糊成一团；只能静态看，点不动 |
| PPT 里贴截图给领导 | 图改了要重新截图、重新贴；还是静态的 |
| 群里发一大段文字描述架构 | 对方要在脑子里重建拓扑，来回问三遍 |

差别在于**改图成本**：以前改一次等于重做一次，现在是"再加一条鉴权路径"一句人话。

## 优点 / 缺点

| 优点 | 缺点 |
|---|---|
| 可交互 HTML，能点、能探索、能直接发链接/文件 | 产物是 HTML，进不了 PR diff、进不了 Wiki 的 Markdown 渲染，得单独找地方放 |
| 可以连续追加修改，不用推倒重来 | **图好看 ≠ 架构正确**：它会忠实画出它以为的结构，错了也画得很专业 |
| 能直接读仓库生成图，带出处 | 只是 Skill，没有校验能力；复杂系统的分层/边界还是要你定 |
| 非技术内容（流程、学习路径）也能画 | 同事要能打开浏览器；发邮件附件里有 HTML 的公司不少见会拦 |

## 安装与使用

```bash
npx skills add tt-a1i/archify -g
```

用法就是直接说人话，然后继续追加："加上鉴权"、"高亮缓存 miss 那条路径"、"换成浅色主题"。

## 三个 agent 怎么接

| Agent | 装到哪 | 调用 |
|---|---|---|
| Pi | `~/.pi/agent/skills/archify/`（项目级 `.pi/skills/`，需项目受信任） | `/skill:archify` |
| Claude Code | `~/.claude/skills/archify/` | `/archify` |
| Codex | `~/.codex/skills/archify/`，或项目 `.agents/skills/archify/` | `$archify` |

README 列的支持范围是 Claude Code、Cursor、Codex CLI、OpenCode，**没有明确写 Pi**。skill 本质是 `SKILL.md` + 静态资源，不依赖某个 agent 的私有能力，手动放到 Pi 的 skill 目录一般能用 —— 这点我没实测，第一次用先拿个小图验证。

## 用起来

```text
/skill:archify 把这个服务的架构画出来：网关 → 两个后端服务 → Redis 缓存 → PostgreSQL，
              标注哪些调用是同步的
```

然后接着追加就行。建议顺序：

1. 先让它读代码/背景，出第一版粗图
2. 逐条补细节（"这条路径要标注超时时间"）
3. 定稿后再换主题、导出，别提前调样式

**典型场景**：给同事/领导讲清一个系统怎么跑的 —— 比在群里贴一段文字描述有效得多。

## 踩坑清单

- **图画得挺好看但结构不对**：先给事实源（仓库路径、接口文档、调用链），别让它猜。
- **改一句全图重画**：一次性把要改的点说完，比一句一句来回快。
- **HTML 打不开 / 样式丢了**：产物引用了外部 JS/CSS，别只拷单个 HTML 文件。
- **想进文档体系**：定稿后导出图片再贴进 Markdown；交互版单独存一份发链接。

**适合谁**：需要反复给不同人讲同一个系统结构的人。一次性讲完就没人再看的场景，一张静态图就够了。
