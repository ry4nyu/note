# Claude Code 文档

Claude Code 是跑在终端里的编程助手：能直接读写项目文件、执行命令、跑测试、用 git 提交和发 PR。本目录按**先用起来，再按需深入**组织。

**环境口径**：Linux / WSL，Claude Code 2.1.x，命令一律是 bash。macOS 基本一致，把 `~/.bashrc` 换成 `~/.zshrc` 即可。Windows 原生的差异（PowerShell 工具、`defaultShell`、Hook 编码）见 [`../windows.md`](../windows.md)；WSL 本身怎么配见 [`../wsl.md`](../wsl.md)。

## 扩展能力怎么选

Claude Code 里「让它按规矩办事」的地方不止一处。先看你要的效果，再选工具：

| 你想要的效果 | 用什么 | 为什么 |
|---|---|---|
| **每次都必须发生**，不依赖模型判断 | [Hook](./Hook.md) | 由 harness 执行，不经过模型，写了就一定跑 |
| 恒真、且很短的项目事实 | `CLAUDE.md`（[规则与记忆](./规则与记忆.md)） | 每轮都在上下文里，代价是每轮都付 token |
| 成体系、要分文件、要按路径生效的约定 | [Rule](./规则与记忆.md) | 自动加载；`paths` 让它只在相关文件上生效 |
| 一类任务的流程、检查单、边界 | [Skill](./Skill与命令.md) | 平时只占一行描述，需要时才展开 |
| 一句话的固定提示词 | [命令文件](./Skill与命令.md) | Skill 的轻量形态，纯参数化展开 |
| 需要独立上下文预算、并行或专职角色 | [Subagent](./Subagent.md) | 单独的上下文窗口，过程不挤占主对话 |
| 接入新工具或数据源 | [MCP](./MCP.md) | 提供的是工具本身 |

一句话：**必须每次发生的放 Hook，恒真的放 `CLAUDE.md`，按需的流程放 Skill，要独立上下文的活放 Subagent，加工具的放 MCP。**

> Rule 和 Skill 都只是**上下文**，模型读到不等于一定照做。真正需要卡死的用 Hook、权限规则、测试或 CI 门禁。

## 文档约定

- 命令默认在 **Linux / WSL** 的 bash 里执行；路径用 `~/code/...` 这类占位符。
- 内容基于 **Claude Code 2.1.x**。这个工具迭代很快，遇到不一致先看 `claude --help`、会话里的 `/help`，再用 `/status`、`/context` 确认实际生效值。
- 标注「实测」的行为来自本机验证；其余按官方文档口径理解，版本升级后可能变化。
- 本仓库的 `.claude/` 在 `.gitignore` 里，这意味着**项目级**的 rules、skills、agents、hooks 直接放进去不会被提交。要共享给同事，先决定是改忽略规则还是走插件分发。
- Codex / Pi 的对应文档在 [`../codex/`](../codex/) 和 [`../pi/`](../pi/)；它们的位置和命令**互不通用**（比如 Claude Code 不读 `.agents/`）。
