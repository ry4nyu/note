# 日常使用

装好并配通模型之后（见 [`安装与配置.md`](./安装与配置.md)），这篇讲每天怎么用。

> 基于 Claude Code 2.1.x、Linux / WSL。Windows 原生差异见 [`../windows.md`](../windows.md)。

## 1. 启动

```bash
cd ~/code/your-project     # 一定要先进项目目录，它按目录加载上下文
claude                     # 进入交互界面
```

常用启动参数：

| 命令 | 作用 |
|---|---|
| `claude "帮我看看这个项目的登录逻辑在哪"` | 带一句初始问题启动 |
| `claude -c` | 继续上一次对话（continue） |
| `claude -r` | 从历史会话列表里挑一个恢复（resume） |
| `claude -p "解释一下 pom.xml"` | 非交互模式，打印结果后退出，适合写脚本 |
| `claude --permission-mode auto` | 只给本次会话指定权限模式 |
| `claude --model sonnet` | 本次会话指定模型 |
| `claude --add-dir ../shared` | 追加一个可访问目录 |
| `claude update` | 升级到最新版 |

## 2. 界面操作

| 操作 | 效果 |
|---|---|
| 直接打字 + 回车 | 提问 / 下指令 |
| `Ctrl+V`（或终端自身的粘贴键） | 粘贴图片给 agent |
| `@文件名` | 引用某个文件，输入 `@` 后有自动补全 |
| `!命令` | 直接执行 shell 命令（如 `!git status`、`!mvn test`） |
| `#内容` | 把这条内容记进记忆文件，下次仍生效 |
| `/命令` | 斜杠命令，输入 `/` 看全部 |
| `Esc` | 打断它正在做的事 |
| `Esc` `Esc` | 回退到之前某一步（rewind），改错了救命用 |
| `Shift+Tab` | 切换权限模式 |
| `Ctrl+J` 或 `\` + 回车 | 输入换行（不是发送） |
| `Ctrl+C` | 清空当前输入；连按两次退出 |
| `Ctrl+D` | 退出 |
| `Ctrl+O` | 打开会话记录视图，可看工具调用和 Hook 结果 |

> 终端复用器（tmux）会截走部分组合键，`Ctrl+B` 尤其常见。冲突时改 tmux 前缀键，或直接在普通终端里用。

## 3. 常用斜杠命令

| 命令 | 作用 |
|---|---|
| `/help` | 帮助，忘了啥命令就敲这个 |
| `/init` | 给当前项目生成 `CLAUDE.md` |
| `/clear` | 清空对话上下文，换话题时用（省 token） |
| `/compact` | 压缩上下文，聊太久时续命（保留要点，丢掉细节） |
| `/context` | 看当前上下文用了多少 |
| `/status` | 看当前模型、账号、API 地址、工作目录、权限模式 |
| `/model` | 切换模型 |
| `/config` | 图形化改配置（主题、权限等） |
| `/permissions` | 管理权限规则，减少重复的「是否允许」弹窗 |
| `/rewind` | 回退对话或代码改动 |
| `/resume` | 恢复历史对话 |
| `/cost` | 看这次会话花了多少（官方账号有参考意义） |
| `/doctor` | 体检，出问题先跑它 |
| `/review` | review 当前分支的改动 |
| `/mcp` | 管理 MCP 外部工具接入 |
| `/hooks` | 查看已注册的 Hook（只读） |
| `/memory` | 查看 / 编辑本次加载的指令文件和自动记忆 |
| `/skills` | 列出可用 Skill |
| `/exit` | 退出（等同 `Ctrl+D`） |

> 命令会随版本增减，以输入 `/` 后弹出的菜单为准。

## 4. 权限模式

Claude 每次要改文件、跑命令，都会先问你。权限模式决定问得多勤。按 `Shift+Tab` 循环切换，界面上会显示当前模式名。

| 模式 | 行为 | 用在什么时候 |
|---|---|---|
| `manual` | 每步都问 | 新手上手，最安全 |
| `acceptEdits` | 改文件不问，跑命令还问 | 已经信任它的时候 |
| `auto` | 分类器逐个判断：安全的放行，可疑的才问你 | 日常开发，最舒服 |
| `plan` | 只读不改，先给方案让你确认 | **改老代码 / 复杂需求强烈推荐先用这个** |
| `bypassPermissions` | 什么都不问 | 只在容器 / 沙箱里用，危险 |

`--permission-mode` 的完整取值（`claude --help` 可查当前版本）：`acceptEdits`、`auto`、`bypassPermissions`、`manual`、`dontAsk`、`plan`。`default` 是 `manual` 的旧名字，两者是同一个模式。

**建议流程**：复杂需求先 `Shift+Tab` 进 plan mode 让它出方案 → 方案没问题 → 切到 auto 让它开干。

### 4.1 把 auto 设为默认

编辑 `~/.claude/settings.json`，改完重开 `claude` 生效：

```json
{
  "permissions": {
    "allow": [],
    "defaultMode": "auto"
  }
}
```

验证：启动后敲 `/status`，或直接问它「当前是什么权限模式」。

想搞清 auto 到底放行什么、拦什么：

```bash
claude auto-mode config      # 当前生效的规则（你的自定义 + 默认值）
claude auto-mode defaults    # 只看默认规则
claude auto-mode critique    # 让 AI 点评你写的规则
claude auto-mode reset       # 清掉自定义，恢复默认
```

深度定制写在 `settings.json` 顶层的 `autoMode` 段，分 `environment` / `allow` / `soft_deny` / `hard_deny` 四类。新手先别动。

> ⚠️ **别把 auto 和 bypassPermissions 搞混**：auto 会拦危险操作（删重要文件、往项目外写、碰密钥等）；`bypassPermissions`（`--dangerously-skip-permissions`）**什么都不拦**，只应在一次性容器 / 沙箱里用。

**两个容易踩的坑**：

1. **auto 写在项目级 `.claude/settings.json` 里不生效**，会被静默忽略——必须写在用户级 `~/.claude/settings.json`，或用 `--permission-mode auto`。`bypassPermissions` 同理。
2. **auto 需要模型 / 套餐支持**。不满足条件时它**不报错**，而是静默退回 Manual——所以「配置写了却不生效」多半不是配置写错。用 `/status` 确认实际生效的模式。

## 5. `CLAUDE.md` 入门

**别手写，让它自己生成。** 在项目根目录启动 `claude`，输入 `/init`：它会扫一遍代码库（README、构建文件、目录结构、现有代码风格），在根目录生成 `CLAUDE.md`。

生成完**必须自己过一遍**：它只能看到代码里能看出来的东西，团队规矩和禁止事项还得你补。

后续维护：

- **零星补充**：对话里输入 `#不要用 var，团队规范要求显式类型`，它会记下来，不用手动开文件。
- **规矩变多**：单个 `CLAUDE.md` 会又长又难维护，还每轮都占上下文。这时拆进 `.claude/rules/`——不带 `paths` 的启动就加载，带 `paths` 的只在碰到匹配文件时才加载。详见 [`规则与记忆.md`](./规则与记忆.md)。
- **技术栈或构建方式改了**：重新跑一次 `/init` 让它更新。

这个文件值得认真写，也是可以提交到 git 的团队资产。

## 6. 工作习惯

1. **说清「在哪、做什么、期望什么」**
   - 差：`登录有问题，修一下`
   - 好：`AuthService.java 的 login 方法，用户输错密码时返回的是 500，应该是 401 加错误提示，帮我改`
2. **复杂需求先出方案再动手**：`先别改代码，读一下 order 模块，告诉我如果要加「超时未支付自动取消」该改哪些地方`，或者直接进 plan mode。
3. **一次只做一件事**：别一口气丢十个需求，也别在一个窗口里聊十几轮。
4. **用 git 兜底**：动手前确认工作区干净，搞砸了 `git checkout .` 就恢复。
5. **让它自己验证**：`改完跑一下相关单测`、`启动服务确认接口能通`，比肉眼检查靠谱。
6. **聊长了记得收**：上下文超过 30% 用 `/compact`，换话题用 `/clear`。上下文塞满之后它会变笨。
7. **别把它当搜索引擎**：问「我项目里 A 和 B 循环依赖了，怎么改」，别问「Spring 循环依赖怎么解决」。和项目无关的问题去网页版问。
8. **发现它思路跑偏**：`Esc` 打断，`Esc` `Esc`（rewind）回退。
9. **异常关机、终端挂了**：`/resume` 接着上次继续。

## 7. 常见问题

**Q：它说改了但文件没变 / 改错文件了**
用 `Esc Esc` 或 `/rewind` 回退。改之前养成 `!git status` 看工作区的习惯。

**Q：聊久了它开始胡说 / 忘记前面说的**
`/compact` 压缩，或者 `/clear` 重开再把关键信息说一遍。

**Q：每次都要点「允许」，烦**
两个办法，可以一起用：

1. 把默认权限模式设成 **auto**（4.1 节）；
2. `/permissions` 里加白名单，例如允许 `Bash(git status:*)`、`Bash(mvn test:*)`。

**Q：auto 模式是不是就不检查了？**
不是。auto 会拦截有风险的操作；`bypassPermissions` 才是完全不检查。见 4.1 的警告。

**Q：怎么让它按团队规范写代码**
写进 `CLAUDE.md` 或 `.claude/rules/`，见第 5 节和 [`规则与记忆.md`](./规则与记忆.md)。

**Q：出问题了怎么反馈 / 看日志**
`/doctor` 看诊断；`/bug` 提反馈。装不上、连不上、上下文窗口太小见 [`安装与配置.md`](./安装与配置.md) 第 8 节。

| 能力 | 用途 | 详见 |

| MCP | 接入外部工具 / 数据源，查数据库、Jira、内部文档 | [`MCP.md`](./MCP.md) |

## 9. 脚本与 CI（headless）

`-p` / `--print` 是非交互模式，适合脚本和流水线：

```bash
claude -p "总结这次改动，并列出风险点"
claude -p "检查项目能不能通过测试" --output-format json
git diff | claude -p "review 这段 diff，只报真实缺陷"
```

写进 CI 时注意：

- 用 `--allowedTools` / `--disallowedTools` 显式收窄工具范围；
- 无人值守时权限提示拿不到回答，提前想好权限模式；
- 别把 API Key 暴露给会执行仓库代码或安装依赖的步骤。
