# 配置：运行环境（Windows 原生 / WSL）

Pi 在 Windows 上有两种跑法，**先选运行环境，再配其它东西**。选错了不会报错，但工具链、路径、换行符、编码的坑会一个个冒出来。

本文只管"Pi 跑在哪个环境里、用哪个 shell"。模型接入见 [`配置-模型接入.md`](./配置-模型接入.md)，权限与工具白名单见 [`配置-权限与规则.md`](./配置-权限与规则.md)。

---

## 1. 怎么选（先看这张表）

| 你在做什么 | 推荐方案 | 原因 |
|---|---|---|
| **Windows 原生应用开发**：.NET / WPF / WinForms、MSBuild、COM、注册表、Windows 服务、驱动、Office 插件、依赖 Windows SDK 或 VS 工具链的项目 | **Windows 原生 + PowerShell 工具** | 这些工具链只在 Windows 上有，WSL 里根本跑不了；或者要跨 `/mnt/c` 调 exe，路径和权限模型全走样 |
| **其它项目**：Java / Go / Node / Python / 前端 / 部署在 Linux 的服务 | **WSL** | 环境与生产一致；shell 脚本、构建工具、路径大小写、换行符都不会跟你作对；文件 IO 也快得多 |
| 只读代码、评审、写文档，不动工具链 | 随你，**原生最省事** | 不需要完整构建环境，少一层隔离就少一类问题 |

一句话：**要在 Windows 上构建/调试的东西，留在 Windows 原生；不依赖 Windows 的东西，进 WSL。**

两种方案可以同时装，但**配置、会话、凭据都不共享**（见第 4 节）。

---

## 2. 方案 A：Windows 原生 + PowerShell（Windows 原生应用开发推荐）

### 2.1 装什么

```powershell
node --version      # 必须 >= 22.19
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pi --version
```

另外装 **Git for Windows**：Pi 的 `!` / `!!` 命令固定走 Bash，不装就没法用（见 2.4）。

### 2.2 让模型用 PowerShell

Windows 上默认分工是这样的：

| 场景 | 默认走什么 |
|---|---|
| 模型调用的 `bash` 工具 | Git Bash |
| 你在输入框敲的 `!` / `!!` 命令 | Bash（**换不掉**） |
| 可选的 `powershell` 工具 | 只有 `defaultTools` 里启用后才存在 |

写进 `C:\Users\你的名字\.pi\agent\settings.json`，把模型面向的 shell 换成 PowerShell：

```json
{
  "defaultTools": ["read", "powershell", "edit", "write", "grep", "find", "ls"]
}
```

只写增量也行（保留你已有的其它工具）：`["-bash", "+powershell"]`。

- `powershell` 工具优先用 `pwsh.exe`（PowerShell 7），找不到再回退系统自带的 Windows PowerShell；启动参数是 `-NoProfile -NonInteractive -ExecutionPolicy Bypass`，公司强制的执行策略仍然优先。
- **只在原生 Windows 下存在**，WSL 里没有这个工具。
- 改完重启 Pi，然后让它跑一条无害命令验证，比如"看一下 PowerShell 版本"。
- **不要同时保留 `bash` 和 `powershell`**，除非你明确想要两套：模型会按心情挑一个，同一件事可能出现两种结果。

### 2.3 Bash 找不到时

Pi 按这个顺序找 Bash：`settings.json` 的 `shellPath` → `Program Files` 下的 Git Bash → `PATH` 上的 `bash.exe`。

Cygwin / MSYS2 这种装在奇怪位置的，指定路径：

```json
{
  "shellPath": "C:\\cygwin64\\bin\\bash.exe"
}
```

> JSON 里 Windows 路径的每个反斜杠要写两个。`shellPath` 支持开头的 `~`。

### 2.4 验证

```text
!printf 'Bash is working\n'     # 验证 Git Bash（! 命令永远走 Bash）
!pwsh -v                        # 验证 PowerShell 7 在 PATH 上
```

### 2.5 Windows 上的快捷键差异

Windows Terminal 占用了部分 `Alt` 组合，Pi 在**原生 Windows 和 WSL 下用同一套替代键**：

| 动作 | 通用默认 | Windows / WSL |
|---|---|---|
| 追加后续任务（排队） | `Alt+Enter` | `Ctrl+Q` |
| 收回排队消息 | `Alt+Up` | `Alt+Q` |
| 反向切模型 | `Shift+Ctrl+P` | `Alt+P` |
| 粘贴图片 | `Ctrl+V` | `Alt+V` |

想用 `Alt+Enter` 这类组合，得改 Windows Terminal 的按键映射。实际生效的键以 `/hotkeys` 为准。

## 3. 方案 B：WSL（其它项目推荐）

### 3.1 先看 WSL 本身

WSL 的安装、镜像模式网络、禁止 interop、代理和排错都在 [`wsl.md`](./wsl.md)，**装 Pi 之前先把它配好**（尤其是 `networkingMode=mirrored` 和 `[interop] enabled=false`，不配后面全是坑）。

### 3.2 装 Pi（装在 WSL 里，不是 Windows 上）

```bash
node --version        # 必须 >= 22.19；Ubuntu 自带的常常过低
# 低就用 nvm：
# curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
# source ~/.bashrc && nvm install 22

npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pi --version
```

也支持官方脚本：`curl -fsSL https://pi.dev/install.sh | sh`。

### 3.3 配置在 WSL 里，Windows 侧那份不生效

| 内容 | WSL 方案下的位置 |
|---|---|
| 设置、密钥、会话、Skill | WSL 里的 `~/.pi/agent/`（如 `/home/你/.pi/agent/`） |
| 模型接入 | 同上，`models.json` / `/login` 都要**在 WSL 里重新配一遍** |
| 环境变量（如网关的 API Key） | 写进 WSL 的 `~/.bashrc` 或 `/etc/environment` |

**Windows 上的 `C:\Users\你的名字\.pi\agent\` 对 WSL 里的 Pi 完全无效** —— 这是最常见的"我明明配了模型但它说没有"的原因。

WSL 下没有 `powershell` 工具，`bash` 就是 Linux 的 Bash，不需要改 `defaultTools`。

### 3.4 代码放哪

- 项目代码放 **WSL 文件系统**（`~/code/...`），不要放 `/mnt/c/...`：跨文件系统读写慢一个数量级，`git status`、`npm install`、编辑器索引都会明显变慢。
- 要用 Windows 侧的工具看文件，用 VS Code 的 Remote-WSL；**不要用 Windows 程序直接编辑 `~/` 里的文件**。

### 3.5 在 IDE 里用

VS Code 用 Remote-WSL 打开项目，然后在终端里直接 `pi`。

---

## 4. 两个都装了会怎样

**没有共享，全部各管各的：**

| 项目 | 原生 Windows | WSL |
|---|---|---|
| 配置目录 | `C:\Users\<you>\.pi\agent\` | `/home/<you>/.pi/agent/` |
| `auth.json` / `models.json` | 各自一份 | 各自一份 |
| 会话历史 | 各自 `sessions/` | 各自 `sessions/` |
| API Key 环境变量 | 用户/系统环境变量 | `~/.bashrc` |
| `!` 命令用的 shell | Git Bash | Linux Bash |

想两边都能用：`models.json` 复制过去，API Key 两边各设一次。会话不通用，接受这一点。

## 5. 常见问题

**Q：Windows 原生下模型老写 Linux 命令，`ls -la` / `rm -rf` 混着来**
`defaultTools` 里没启用 `powershell`，它就在用 Git Bash。按 2.2 改，然后重启 Pi。

**Q：换到 PowerShell 后它还在用 bash**
检查改的是不是 `~/.pi/agent/settings.json`，以及 `!` 命令不受这个设置影响（`!` 永远走 Bash）。`/session` 或启动头部能看到实际加载的设置。

**Q：WSL 里 `pi` 命令找不到**
Pi 只装在 Windows 上了。在 WSL 里执行 `which pi`，为空就按 3.2 装。

**Q：WSL 里模型列表是空的 / 提示未登录**
Windows 那份配置不跨环境。在 WSL 里跑一次 `pi`，确认 `~/.pi/agent/models.json` 存在且 API Key 环境变量在 `env | grep` 里能看到。

**Q：WSL 里 `code .` / `explorer.exe` 不能用**
这是 `wsl.md` 第 3 节故意关掉 interop 的结果。需要就在那个文件里改成 `enabled = true`，或者用 Remote-WSL。

**Q：项目在 `/mnt/c` 上，能跑吗**
能跑，但慢，而且 Windows 和 Linux 的换行符、大小写、文件监听差异会持续制造问题。能用 WSL 就把代码挪进 `~/`。
