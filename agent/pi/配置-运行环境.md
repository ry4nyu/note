# 配置：运行环境（Linux / WSL）

Pi 装在 **WSL（或纯 Linux）里跑**，代码也放 Linux 文件系统。本文只管这件事相关的装法、路径和 IDE 搭配。模型接入见 [`配置-模型接入.md`](./配置-模型接入.md)，权限与工具白名单见 [`配置-权限与规则.md`](./配置-权限与规则.md)。

**Windows 原生环境**（依赖 .NET / MSBuild / COM / Windows 服务的项目）的差异 —— `powershell` 工具、Git Bash、`shellPath`、快捷键替代键 —— 统一在 [`../windows.md`](../windows.md) 第 5 节。

---

## 1. 装在哪

| 你在做什么 | 用哪个 |
|---|---|
| 其它项目：Java / Go / Node / Python / 前端 / 部署在 Linux 的服务 | **WSL 或 Linux**（默认选择） |
| Windows 原生应用开发：.NET / WPF / WinForms、MSBuild、COM、注册表、Windows 服务、驱动、Office 插件 | Windows 原生，见 [`../windows.md`](../windows.md) |
| 只读代码、评审、写文档 | 随你，WSL 里一样跑 |

一句话：**不依赖 Windows 工具链的东西，全部进 WSL。**

> WSL 本体还没装？先看 [`../wsl.md`](../wsl.md)：镜像模式网络（代理才不会断）、`[interop] enabled=false`、文件互访和排错都在那里。

## 2. 安装

```bash
node --version        # 必须 >= 22.19；Ubuntu 自带的常常过低
```

低了就用 nvm 装一个：

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc && nvm install 22
```

然后装 Pi：

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pi --version
```

也支持官方脚本：`curl -fsSL https://pi.dev/install.sh | sh`。

> `--ignore-scripts` 不是可选项的仪式：Pi 不需要安装脚本，跳过它省掉一类供应链风险。

---

## 3. 目录与配置位置

| 内容 | 位置 |
|---|---|
| 设置、密钥、会话、Skill | `~/.pi/agent/`（如 `/home/you/.pi/agent/`） |
| 模型接入 | 同上：`models.json` / `/login` |
| 会话历史 | `~/.pi/agent/sessions/` |
| 环境变量（如网关的 API Key） | `~/.bashrc` 或 `/etc/environment` |

用 `PI_CODING_AGENT_DIR` 可以整体换目录，`PI_CODING_AGENT_SESSION_DIR` 单独换会话目录。

**配置不跨环境共享**：Windows 侧的 `C:\Users\你\.pi\agent\` 对 WSL 里的 Pi 完全无效 —— 这是"我明明配了模型它说没有"最常见的原因。反过来也一样。

---

## 4. 代码放哪

- 项目代码放 **Linux 文件系统**（`~/code/...`），不要放 `/mnt/c/...`：跨文件系统读写慢一个数量级，`git status`、`npm install`、编辑器索引都会明显变慢。
- 要用 Windows 侧的工具看文件，用 VS Code 的 **Remote-WSL**；**不要用 Windows 程序直接编辑 `~/` 里的文件**，换行符和权限会走样。
- 只在真要交换文件时用 `/mnt/c`（拷个安装包、导个文档），平时不放在那儿开发。

---

## 5. shell 与工具

- Linux / WSL 下 `bash` 工具就是你的 bash，`!` / `!!` 命令也是同一个 shell，**不需要改 `defaultTools`**。默认工具集：`read`、`bash`、`edit`、`write`。
- 想加只读工具或收紧权限，见 [`配置-权限与规则.md`](./配置-权限与规则.md) 第 2 节：

  ```bash
  pi --tools read,grep,find,ls -p "评审这个模块"   # 只读
  pi -nt                                            # 工具全关
  ```

- 想换登录 shell（fish、zsh）：Pi 的 `bash` 工具走的是 bash，换 shell 只影响你自己手敲的 `!` 命令，不影响模型。别为此改 `settings.json`。

---

## 6. 代理

- **WSL 镜像模式 + `autoProxy=true`**（[`../wsl.md`](../wsl.md) 第 2 节）会自动把 `http_proxy` / `https_proxy` 注入发行版，Pi 不用额外配。
- 想给 Pi 单独指定，写用户级 `~/.pi/agent/settings.json`（**`httpProxy` 只能写在用户级**）：

  ```json
  { "httpProxy": "http://127.0.0.1:10808" }
  ```

- 或者用 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量。
- **`sudo` 不继承代理**：`sudo -E <命令>`，或者给 apt 单独配 `/etc/apt/apt.conf.d/95proxy`。

---

## 7. 在 IDE 里用

- **VS Code / Cursor**：装 Remote-WSL，打开项目后在 IDE 终端里直接 `pi`。
- **JetBrains（IntelliJ / GoLand）**：连 WSL 远端解释器或用 Gateway 打开，同样在终端里 `pi`。
- **长期跑的任务**：套 `tmux` 或 `zellij`，断连不丢会话。

## 8. 常见问题

**Q：`pi: command not found`**
`source ~/.bashrc` 或重开终端。还不行看 `npm config get prefix` 的 `bin` 目录在不在 `PATH` 里。

**Q：模型列表是空的 / 提示未登录**
确认 `~/.pi/agent/models.json` 存在、`apiKey` 指向的环境变量在 `env | grep` 里能看到（改完 `~/.bashrc` 要 `source` 或重开终端）。

**Q：`code .` / `explorer.exe` 不能用**
这是 [`../wsl.md`](../wsl.md) 第 3 节故意关掉 interop 的结果。用 Remote-WSL 打开项目即可，不必为此重新开 interop。

**Q：项目在 `/mnt/c` 上，能跑吗**
能跑，但慢，而且换行符、大小写、文件监听差异会持续制造问题。能挪就挪进 `~/`。

**Q：WSL 里能不能当沙箱用**
不能。WSL 只是换了环境，Pi 仍以你当前用户权限读写执行。要边界就用容器，见 [`配置-权限与规则.md`](./配置-权限与规则.md) 第 2 节。
