# 配置：权限、工具与项目规则

Pi 的默认立场和 Claude Code / Codex 不一样，**先理解这一点再谈配置**：

**Pi 没有 `auto` 权限模式，也没有"逐次审批"。它默认不问你** —— 你看到的是每一次工具调用和它的结果（`Ctrl+O` 展开），而不是每个操作前的弹窗。官方立场是：审查记录**不构成安全边界**，真正的边界只有两个：项目信任（决定加载什么）和工具白名单（决定能做什么），加上操作系统/容器这一层。

本文分三块：项目信任（第 1 节）、工具白名单与隔离（第 2 节）、项目规则 `AGENTS.md`（第 3 节）。

---

## 1. 闸门一：项目信任（project trust）

它管的是"这个目录里的东西要不要**加载并执行**"。工作目录里存在下面任一资源时，Pi 必须先拿到信任决定：

- `.pi/settings.json`
- `.pi/mcp.json`
- `.pi/extensions`、`.pi/skills`、`.pi/prompts`、`.pi/themes`
- `.pi/SYSTEM.md` 或 `.pi/APPEND_SYSTEM.md`
- 当前目录或祖先目录里的项目级 `.agents/skills`

（只有空的 `.pi` 目录不需要信任。）

决定按这个顺序产生：

1. 命令行 `--approve` / `--no-approve`
2. 用户级/命令行扩展处理 `project_trust` 事件（第一个给出 yes/no 的扩展说了算）
3. 已保存的决定（`~/.pi/agent/trust.json`，就近生效）
4. 全局设置 `defaultProjectTrust`（默认 `"ask"`）

```powershell
pi --approve        # 本次直接信任
pi --no-approve     # 本次完全不加载项目本地资源
```

交互界面里用 `/trust` 保存决定，之后不再问。

> **非交互模式没有信任弹窗**：`pi -p` / `--mode json` / `rpc` 下，`defaultProjectTrust: "always"` 才加载项目资源，`"ask"` / `"never"` 一律跳过。自动化跑的时候显式给 `--approve` 或 `--no-approve`。

### 上下文文件不受这个闸门保护

`AGENTS.md`、`AGENTS.override.md`、`CLAUDE.md` **不管项目可不可信都会被加载**。也就是说"只读看一下别人的仓库"时，仓库里的 `AGENTS.md` 已经进模型上下文了 —— 把它当**不可信输入**看待。真要干净，用 `--no-context-files`。

### 项目信任不是万能边界

Pi 在解析信任之前就要读项目里的 `sessionDir`（为了找会话），所以拒绝了信任也挡不住这一步。信任也不限制工具能访问什么 —— 见下一节。

## 2. 闸门二：工具白名单

这是 Pi 唯一"削弱能力"的硬开关，比审批模式实在得多：

```powershell
pi --tools read,grep,find,ls -p "评审这个模块"    # 只读，物理上改不了文件
pi --exclude-tools bash,write,powershell          # 只禁掉危险的
pi -nt                                            # 工具全关（扩展工具也关）
pi -nbt                                           # 只关内置工具
```

要长期生效就写进 `~/.pi/agent/settings.json`：

```json
{
  "defaultTools": ["read", "powershell", "edit", "write", "grep", "find", "ls"]
}
```

规则：

- 只写工具名 = **替换**默认集合（默认是 `read`、`bash`、`edit`、`write`）。
- 写 `+name` / `-name` = 在已有集合上增删，例如 `["-bash", "+powershell"]`。
- 项目 `.pi/settings.json` 叠加在用户设置之上。
- `/reload` 只补新加的工具，**不会**把删掉的加回来。

窗口的 shell 该选 `powershell` 还是 `bash`，见 [`配置-运行环境.md`](./配置-运行环境.md)。

### 真正的隔离：容器或虚拟机

Pi 用它所属操作系统用户的权限读写和执行文件，**没有内置沙箱**。要跑"不可信或无人值守"的任务，唯一靠谱的办法是把整个 Pi 放进容器 / 虚拟机 / 沙箱，只暴露这次任务需要的目录、凭据和网络。

### 几条硬要求

1. **不要在公司主力机器上直接跑未审阅的 `.pi/extensions/`** —— 扩展在 Pi 进程内执行，权限和 Pi 完全一样。
2. **能只给只读就给只读**：评审、调研类任务一律 `--tools read,grep,find,ls`。
3. **凭据给最小范围、最短有效期**，能不给就不给。
4. **改动前后都看 git**：`git status` / `git diff` 是唯一的回退手段。Pi 的 `/tree`、`/fork`、`/clone` 管的是**对话**，不回滚文件。
5. **分享会话前先自己看一遍**：`/export`、`/share`、`pi-debug.log` 里可能有代码和凭据。

## 3. 项目规则：AGENTS.md

`AGENTS.md` 是让 Pi 少犯错的性价比最高的一招。Pi 在**工作目录及其所有父目录**里找上下文文件，只要 Pi 运行在该目录或其子目录下就生效。

可用文件名：`AGENTS.override.md`、`AGENTS.md`、`AGENTS.MD`、**`CLAUDE.md`**、`CLAUDE.MD`（从 Claude Code 迁过来可以直接复用 `CLAUDE.md`）。同目录下 `AGENTS.override.md` 顶掉同目录的 `AGENTS.md` / `CLAUDE.md`（不影响其它目录）。

用户级规则放 `~/.pi/agent/AGENTS.md`，对所有工作目录生效。

在项目根目录建一个 `AGENTS.md`，写清这些：

```markdown
# 项目说明

## 技术栈
Spring Boot 3.x + MyBatis-Plus + MySQL 8 + Redis，JDK 17

## 构建与测试
- 构建：mvn clean package -DskipTests
- 单测：mvn test -Dtest=XxxTest
- 启动本地环境：见 README

## 代码规范
- 分层：Controller / Service / Mapper，不要跨层调用
- 统一返回体 Result<T>，不要直接返回实体
- 日志用 @Slf4j，禁止 System.out.println
- 新增接口必须补 Swagger 注解

## 禁止事项
- 不要动 src/main/resources/application-prod.yml
- 不要引入新的第三方依赖，先问我
- 数据库变更一律走 Flyway 脚本，不要手写 DDL
```

- 临时关掉上下文加载：`pi --no-context-files`（排查"到底是哪条规则在起作用"时很好用）。
- 改完 `/reload` 生效；启动头部会列出实际加载了哪些指令和资源。
- ⚠️ **不要把密码、Token 或内部密钥写进这个文件**，它会被完整发给模型。

## 4. 相关文件一览

| 文件 | 作用 | 受项目信任保护 |
|---|---|---|
| `~/.pi/agent/settings.json` | 用户级设置：默认模型、`defaultTools`、`compaction`、`httpProxy` | 用户级，不涉及 |
| `./.pi/settings.json` | 项目级设置 | 是 |
| `~/.pi/agent/trust.json` | 保存的信任决定 | 用户级 |
| `./AGENTS.md` / `./CLAUDE.md` | 项目规则 | **否，总是加载** |
| `./.pi/extensions/`、`./.pi/skills/` | 项目扩展与 Skill | 是 |
| `./.agents/skills/` | 项目 Skill（本仓库用的位置） | 是 |

相关文档：[`Extension使用指南.md`](./Extension使用指南.md)（扩展的权限风险）、[`skill使用指导.md`](./skill使用指导.md)（Skill 的加载与信任）。
